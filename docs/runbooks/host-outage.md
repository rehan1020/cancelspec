# Runbook: Host Outage & DNS Failover

## Context

CancelSpec is hosted across two independent static providers:
- Primary: Cloudflare Pages (`cancelspec.org` / `*.pages.dev`)
- Secondary: GitHub Pages (`cancelspec.github.io`)

Because all site content and tools are 100% static client-side files, failover requires no database replication or session synchronization.

## Procedures

### 1. Detect Outage
- An alert is generated by the daily monitor job (`daily.yml`) or external status monitoring when HTTP response codes are 5xx or timed out.
- Confirm outage scope using `curl -I https://cancelspec.org/` and provider status dashboards (e.g., `cloudflarestatus.com` or `www.githubstatus.com`).

### 2. DNS Failover to Secondary Host
If Cloudflare Pages is experiencing an extended outage:
1. Log into your authoritative DNS manager (Cloudflare DNS or registrar).
2. Change the `CNAME` record for `@` or `www` to point to `cancelspec.github.io`.
3. Set TTL to 300 seconds (5 minutes) during failover.
4. Verify HTTPS certificate provisioning on GitHub Pages (custom domain settings in repository).

### 3. Verification Post-Failover
1. Verify site loads in a private browser window: `curl -IL https://cancelspec.org/tool/`.
2. Verify strict CSP headers and client-side statement scanner function offline.
3. Test a synthetic statement file in the tool.

### 4. Restoration Post-Incident
1. Once the primary host has fully recovered, test its direct endpoint.
2. Revert DNS `CNAME` records back to Cloudflare Pages.
3. Return TTL to standard setting (auto / 1 hour).
4. Log an incident post-mortem issue in GitHub issues.
